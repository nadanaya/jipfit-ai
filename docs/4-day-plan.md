# 1인 팀 4일 실행계획

## Day 1 — 문제와 핵심 엔진 고정

- 문제 문장·대상 사용자·제외 범위 확정
- 주거비 계산식과 정책 출력 형식 결정
- 합성 데이터 생성기, 모델 베이스라인, SQLite 스키마 구현
- 완료 기준: CLI에서 한 입력의 전체 JSON 결과 출력

## Day 2 — 발표 가능한 제품화

- Streamlit 입력·결과 화면 구현
- 정책 사전진단 근거와 공식 링크 연결
- 로딩·오류·빈 상태 정리
- 완료 기준: 인터넷 없이 기본 데모 3회 연속 성공

## Day 3 — 검증과 이야기

- 단위·통합 테스트, SQL 검증
- 모델 지표·오류 분석·한계 문서화
- 7장 발표 구성과 3분 대본 작성
- 완료 기준: `python scripts/validate_project.py` 통과

## Day 4 — 제출 안정화

- 화면 캡처와 데모 영상 촬영
- README·팀명·서비스명·한 줄 소개 통일
- 예상 질문 리허설, 실패 시 대체 흐름 점검
- 최종 ZIP 생성·다른 PC에서 재설치 확인
- 완료 기준: 새 폴더에서 `setup_windows.bat` 또는 README 명령으로 재현

## 1인 운영 원칙

- 기능 추가보다 데모 실패 가능성 제거를 우선한다.
- 매일 마지막 30분은 문서·커밋·백업에 사용한다.
- 실시간 API는 선택 기능으로 두고 핵심 결과는 로컬 데이터로 보장한다.
