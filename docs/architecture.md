# 시스템 아키텍처

```text
사용자 입력
  ├─ 소득·자산·부채·가구원수
  ├─ 희망 지역
  └─ 보증금·월세·관리비
          │
          ▼
┌──────────────────────────────┐
│ Streamlit UI (app.py)        │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ Application Service          │
│ src/service.py               │
├──────────────┬───────────────┤
│              │               │
▼              ▼               ▼
Affordability  ML Classifier   Policy Engine
투명 계산       3단계 위험       조건별 설명
│              │               │
└──────────────┴───────────────┘
               ▼
 결과 카드 · 정책 후보 · 다음 행동
               │
               ▼
 SQLite 익명 분석 로그(선택)
```

## 주요 파일

- `src/affordability.py`: 권장 주거비와 현금흐름 계산
- `src/train.py`: 기준 모델과 후보 모델 비교·저장
- `src/predict.py`: 모델 추론
- `src/policy_engine.py`: 정책별 설명 가능한 사전진단
- `src/service.py`: 전체 결과 조합
- `src/database.py`: 파라미터 바인딩을 사용한 최소 로그 저장
- `app.py`: 발표용 웹 화면

## 데이터 흐름과 누수 방지

모델은 소득, 보증금, 월세, 관리비, 부채 등 원시 입력만 사용한다. 타깃을 직접 계산한 `주거비 비율`이나 `잔여 생활비`는 학습 입력에 넣지 않아 명시적인 타깃 누수를 피한다. 다만 타깃 자체가 합성 규칙에서 생성되므로 현실 배포 전에 실제 데이터로 외부 검증해야 한다.
